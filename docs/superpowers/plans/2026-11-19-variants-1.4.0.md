# Pixelgrid 1.4.0: Agency variant implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Agency starting point (its own colours, display font, header, footer, pages, case studies and journal) on the 1.3.0 variant system, after fixing the two items parked from 1.3.0, released as 1.4.0.

**Architecture:** Agency is one more variant file (`inc/variants/agency.php`) plus a style variation (`styles/agency.json`), its patterns (`patterns/agency-*.php`) and images. The 1.3.0 setup and design layers get small, general extensions that Agency needs and News and Shop will reuse: child pages, per-variant images, variant-driven screen labels, and safer re-apply. No fixed format from 1.3.0 changes.

**Tech Stack:** WordPress 7.1 block theme (theme.json v3), PHP 7.4+, WP-CLI test harness in `tests/`, phpcs (WPCS 3) installed outside the repo.

**Spec:** `docs/superpowers/specs/2026-11-18-variants-design.md` (sections 2, 3, 5, 6.1 to 6.4, 6.6, 6.7, 7, 10). Carried-forward notes from 1.3.0: `.superpowers/carry-forward-1.3.0-ledger.md` in the main checkout (git-ignored, local).

## Global Constraints

- Block theme, theme.json version 3, `Requires at least: 6.6`, `Tested up to: 7.1`, `Requires PHP: 7.4`.
- Text domain `pixelgrid`; every user-facing string translatable, in PHP patterns, not `.html` files; prefix `pixelgrid_` (functions, options), `pixelgrid/` (pattern slugs), `pixelgrid-` (pattern categories, handles).
- Nothing is created or changed until the user ticks options and clicks a button on Appearance > Pixelgrid setup. No external calls at runtime, no remote files, no bundled plugins.
- Fixed formats from 1.3.0 do not change:
  - options `pixelgrid_starter_variant`, `pixelgrid_starter_design`, `pixelgrid_starter_schema`, `pixelgrid_starter_terms`, `pixelgrid_starter_reading`, `pixelgrid_starter_done`
  - marker `_pixelgrid_starter` = `{variant}:{key}`
  - the structure of `pixelgrid_starter_design`
  - IT's existing keys, including `image-N`
- A 1.3.0 site updated to 1.4.0 looks and behaves the same until its owner chooses otherwise.
- Every tone of every variant: text on background at least 4.5:1, text on hover colour at least 4.5:1.
- All four variants keep the Pixelgrid identity: 24-cell grid, mosaics, section tones, condensed uppercase headings, pixel-notch images.
- Fonts and images bundled, GPL-compatible, credited in `readme.txt`. Images are own work generated by code.
- No hardcoded post, term, menu or media IDs in theme files.
- phpcs (WordPress standard, testVersion 7.4-) reports 0 errors and 0 warnings on `functions.php` and `inc/` before release.

## Review Focus

1. **The user customised their header, deleted it, then runs setup again.** Setup must not recreate it over their deletion or lose the backup of their earlier customisation. Test in Task 1.
2. **Agency is applied on a site that has IT starter content.** It is blocked with a clear reason, and nothing changes. Test in Task 6.
3. **The user edits an Agency case-study page, then removes starter content.** The page is trashed (1.2.0 behaviour), but the page tree must not leave orphaned child pages. Test in Task 6: parents and children all end in the trash together.
4. **A case-study link inside the Work page.** It must work under plain and pretty permalinks. Test in Task 2 (fix_links for child pages) and Task 6 (links resolve).
5. **Agency's style variation is picked from Styles > Browse styles without running setup.** Its font must load, because the face lives in the base theme.json. Test in Task 3.

### Task 1: Close the parked 1.3.0 design items

**Files:**
- Modify: `inc/starter-design.php`, `inc/starter-screen.php`
- Test: `tests/test-design.php`, `tests/test-screen.php`

**Interfaces:**
- Changes:
  - `pixelgrid_design_apply( array $variant ): array|WP_Error`. It returns `WP_Error( 'pixelgrid_style_missing' )` before writing anything when `style` is not '' and the file is missing or not valid JSON. On success it returns the existing array with `skipped`.
  - `pixelgrid_design_undo(): array` adds `revisions` (bool): true only when the user styles post has at least one revision.
  - The `kept` and `skipped` entries become `"{type}:{slug}"` (for example `wp_template_part:header`, `wp_template:home`), plus `styles` for styles.
- Rules:
  - **Re-apply, recorded item gone.** A recorded entity whose post is missing or trashed is treated as a user change: no write, record kept as is, reported in `skipped`. The user's pre-setup backup in a `created=false` record is never replaced.
  - **New `wp_template` title.** It uses core's default title for that slug from `get_default_block_template_types()`, and falls back to the slug.
  - **`pixelgrid_starter_kept_label()`** maps `wp_template_part:header` to "Header", `wp_template_part:footer` to "Footer", and other `wp_template:*` slugs to the core template title.
  - **"Styles > Revisions" hint** shows only when `revisions` is true.
  - **`pixelgrid_starter_create()`** passes the `pixelgrid_style_missing` error through, with nothing created.
- The design state option keeps its structure; only return arrays change.

### Task 2: General setup extensions (child pages, images, labels)

**Files:**
- Modify: `inc/variants.php`, `inc/starter-content.php`, `inc/starter-screen.php`
- Test: `tests/test-variants.php`, `tests/test-starter.php`, `tests/test-screen.php`

**Interfaces:**
- **Variant keys** (new optional, with defaults):
  - `pages` tuples may have a 4th element: a parent page slug (default '').
  - `content_labels`: `array( 'pages' => string, 'posts' => string, 'reading' => string )`, translatable sentences shown next to the checkboxes. Default ''; empty falls back to a generic sentence built from counts.
  - `design_note`: string, a translatable sentence about what applying this variant's design does to Styles. Default ''; empty falls back to a generic sentence.
- **`pixelgrid_variants()` guard.** It skips (and does not fatal on) a variant file that does not return an array.
- **Post `image` value:** an int (IT, unchanged, file `assets/images/plate-N.webp`, key `image-N`) or a theme-relative path string (key `image-` plus the file name without extension, for example `image-agency-03`).
- **`pixelgrid_starter_create()`:**
  - Inserts parents before children (pages sorted so any page whose parent is in the list comes after it) and sets `post_parent`.
  - Page markers stay `page-{slug}`; slugs are unique per variant.
- **`pixelgrid_starter_fix_links()`** also maps `?pagename={parent}/{slug}` to the real permalink.
- **`pixelgrid_starter_remove()`** trashes children before parents.
- **Screen:**
  - Content checkbox labels and the Design description come from the selected variant's `content_labels` and `design_note`.
  - Because variant choice changes them, the screen renders one label set per variant, wrapped in elements shown or hidden by the radio choice. This uses a small inline script on this page only, and works without JS by showing all sets under a heading per variant.
