# Pixelgrid 1.6.0: Shop variant implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Shop starting point on WooCommerce as 1.6.0. It has its own palette, a two-row header with search, account and mini-cart, grid-styled WooCommerce templates, a shop home, and 12 pixel-art products. This completes the four starting points.

**Architecture:**
- Shop is one more variant file, `inc/variants/shop.php`, with `requires => array( 'woocommerce' )`. The screen already disables the card and links to the plugin installer when WooCommerce is missing.
- Patterns that contain WooCommerce blocks are registered in PHP on `init`, only when WooCommerce is active (`inc/shop-patterns.php`). They are never placed in `patterns/`.
- The WooCommerce templates are neutral theme files in `templates/`. Any Pixelgrid site with WooCommerce gets grid-styled shop pages; the Shop variant adds its colours, header and footer on top through setup.
- Setup gains products: simple products created through WooCommerce's own CRUD classes, marked like other starter content, and removed with it.

**Tech Stack:** WordPress 7.1 block theme (theme.json v3), PHP 7.4+, WooCommerce (latest stable, test site only, never bundled), the WP-CLI test harness in `tests/`, and phpcs (WPCS 3).

**Spec:** `docs/superpowers/specs/2026-11-18-variants-design.md`, sections 2, 5, 6.2 (Shop row), 6.3 (E-commerce), 6.4, 6.6, 6.7 and 10. Rulings from 1.4.0 and 1.5.0 are in each worktree's `.superpowers/sdd/*/progress.md`.

## Global Constraints

- **Platform:** block theme, theme.json version 3, `Requires at least: 6.6`, `Tested up to: 7.1`, `Requires PHP: 7.4`.
- **WooCommerce is optional:**
  - With WooCommerce inactive, nothing breaks, there are no PHP notices and no shop patterns appear.
  - The theme never bundles, downloads or installs WooCommerce. It only links to Plugins > Add New.
- **Text domain and prefixes:**
  - The text domain is `pixelgrid`, and every user-facing string is translatable.
  - Prefixes are `pixelgrid_`, `pixelgrid/` and `pixelgrid-`.
- **Consent:** nothing is created until the user ticks options and clicks the button.
- **Fixed formats from 1.3.0 do not change:**
  - the options
  - the marker `_pixelgrid_starter` = `{variant}:{key}`
  - the design backup structure
- **New options are additive only.** Example: `pixelgrid_starter_product_cats`.
- **Upgrades:** a 1.5.0 site with IT, Agency or News starter content, updated to 1.6.0, looks and behaves the same and removes cleanly.
- **Contrast:** every tone of every variant passes 4.5:1 for text on background and for text on hover.
- **Identity:** the Pixelgrid identity is kept, and product images get the pixel-notch.
- **Images:** product pictures are pixel-art illustrations generated by code (`tools/make-products.php`), own work under GPL. No stock photos and no AI images.
- **No hardcoded IDs** of posts, terms, products or media in theme files.
- **phpcs:** the WordPress standard and PHPCompatibilityWP 7.4- report 0 errors and 0 warnings on `functions.php`, `inc/` and `patterns/`.
- **Test-site lessons:**
  - Run setup as `--user=freshadmin`.
  - Use plain permalinks.
  - Do phone checks in a 390 px iframe.
  - Bump the Version in style.css for pattern-cache refresh.
  - Never `git add -A` the `styles/` folder. `styles/news.json` is a locally blocked, untracked file.

## Review Focus

1. **WooCommerce is deactivated after Shop setup.**
   - Products stay in the database. The front end and admin show no fatal or notice.
   - The header part, saved with WooCommerce blocks, degrades: core shows its "block not available" placeholder only in the editor and nothing on the front end.
   - Remove still works and trashes the products by post type, without WooCommerce classes.
   - Tests in Task 6.
2. **The user already has products, product categories or WooCommerce pages.**
   - Setup never edits them.
   - Existing product categories with the same slug are reused and never deleted on remove.
   - Test in Task 1.
3. **Shop setup is run twice.**
   - No duplicate products, images or terms.
   - Prices the user changed are kept, because existing products are found and left alone.
   - Test in Task 1.
4. **Cart and checkout are used with the Shop design applied.**
   - The WooCommerce cart and checkout blocks render inside the grid with readable contrast.
   - Adding to cart from a product page works.
   - Checked in Task 7 in the browser.
5. **A non-Shop variant site that has WooCommerce active.**
   - The grid-styled templates apply, and IT, Agency and News look unchanged elsewhere.
   - No shop patterns get inserted into their pages.
   - Test in Task 4.

### Task 1: Products in setup, and the WooCommerce test harness

**Files:**
- Modify:
  - `tests/bin/site.sh`: `up --woo` copies `woocommerce/` from `$PIXELGRID_WOO_CACHE`, defaulting to the scratchpad `woocommerce` folder. It activates the plugin, skips the setup wizard with `woocommerce_onboarding_profile` and `woocommerce_task_list_hidden`, and runs `wc tool run install_pages` to create its pages.
  - `inc/starter-content.php`
- Test: `tests/test-starter.php` (add), `tests/test-shop.php` (new, run with `--woo`).

**Interfaces (used by Task 6):**
- Variant key `products`: a list of items with these fields:
  - `key`, `name`, `category` (product_cat slug), `price` (string, e.g. `'18.00'`), optional `sale`
  - `short` (short description), `content` (block markup), `image` (theme path)
- Variant key `product_categories`: slug → name.
- `pixelgrid_starter_product_categories( array $def ): array` returns slug → term_id.
  - It reuses existing terms.
  - It records only the terms it created, in the new option `pixelgrid_starter_product_cats`.
- In `pixelgrid_starter_create()`:
  - Options key `posts` also covers products. The Shop content label says "Twelve products and three journal posts".
  - Products are created only when `class_exists( 'WC_Product_Simple' )`.
  - Each product gets the marker `{variant}:product-{key}`.
  - An existing marked product is found and left alone.
  - The image goes through `pixelgrid_starter_image()`.
  - The result gains a `products` count.
- `pixelgrid_starter_remove()`:
  - Trashes marked posts of type `product` by query, without needing WooCommerce.
  - Deletes recorded product categories when no non-trashed object uses them, using `pixelgrid_starter_term_in_use`.
